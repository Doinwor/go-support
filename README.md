# GO Support

Публичная система обращений экосистемы GO: статический сайт на GitHub Pages и
десктопная программа администратора на Java (хранится только локально, в
репозиторий не попадает).

- **Сайт:** https://doinwor.github.io/go-support/
- **Репозиторий:** https://github.com/Doinwor/go-support

## Как это устроено

```
Пользователь → create.html (Google Form) → Google Таблица → CSV
                                                    ↓
                              Java-админка (локально) → GitHub API
                                                    ↓
                    website/data/tickets/*.json + index.json
                                                    ↓
                          GitHub Actions → GitHub Pages → сайт
```

Сайт не имеет бэкенда: он читает JSON-файлы прямо из репозитория. Ответы
администратора также хранятся в этих файлах, поэтому история обращений
публична и версионируется.

## Структура репозитория

```
go-support/
├── website/
│   ├── index.html            # лента обращений: поиск, статусы, проекты
│   ├── create.html           # страница с встроенной Google Form
│   ├── ticket.html           # обращение ?id=... и ответ администрации
│   ├── assets/
│   │   ├── css/style.css     # фиолетовая светлая тема
│   │   ├── js/app.js         # логика ленты, поиска и страницы обращения
│   │   └── img/logo.png
│   └── data/
│       ├── index.json        # краткая сводка для главной (собирает CI)
│       └── tickets/          # по одному JSON на обращение
├── .github/workflows/
│   ├── build-index.yml       # пересборка index.json при изменении заявок
│   └── deploy-pages.yml      # публикация website/ на GitHub Pages
└── README.md
```

`admin-app/` существует только на компьютере администратора и добавлен в
`.gitignore`. В публичном репозитории его нет.

## Технологии сайта

- Tailwind CSS (CDN) — фиолетовая палитра, светлый фон, тени.
- Fuse.js (CDN) — нечёткий поиск по заголовку, тексту и автору.
- GitHub Actions — сборка `index.json` и деплой Pages.

## Локальный запуск сайта

Из-за `fetch` нельзя открывать страницы через `file://` — нужен статический сервер:

```bash
python -m http.server 8000 --directory website
# http://localhost:8000
```

## Google Form на странице `create.html`

Кнопка «Оставить обращение» ведёт на `create.html`. Пока форма не подключена,
там показывается заглушка. Чтобы встроить форму:

1. Создайте Google Form (см. раздел «Настройка Google Forms»).
2. Нажмите **Отправить → `< >` (HTML)** и скопируйте `src` из `iframe`.
   Ссылка должна заканчиваться на `?embedded=true`.
3. Откройте `website/assets/js/app.js` и заполните константу вверху файла:

```js
const FORM_EMBED_URL =
  "https://docs.google.com/forms/d/e/1FAIpQLS.../viewform?embedded=true";
```

После этого заглушка скроется, форма появится на странице, а внизу будет
ссылка «Открыть форму в новой вкладке».

## Формат данных

Каждое обращение — отдельный файл `website/data/tickets/{id}.json`.
`id` формируется как `дата-время-ник`, например `2026-10-31-1423-vasya`.

```json
{
  "id": "2026-10-31-1423-vasya",
  "author": "Вася",
  "scope": "studio",
  "project_label": "i. студия / Утилиты / Rutube Downloader",
  "title": "Не качает видео",
  "text": "Вставляю ссылку, а программа пишет ошибку…",
  "screenshot": "https://example.com/screenshot.png",
  "date": "2026-10-31T14:23:00",
  "status": "answered",
  "admin_reply": {
    "text": "Привет! Проблема в обновлении Rutube — мы уже чиним.",
    "date": "2026-10-31T18:00:00",
    "admin_name": "Главный Админ",
    "admin_avatar": "assets/img/logo.png"
  }
}
```

- `status`: `open` (ожидает ответа), `answered` (есть ответ), `closed` (закрыто).
- `scope`: `ecosystem` (GO Ecosystem) или `studio` (i. студия).
- `admin_reply` может отсутствовать, пока ответа нет.
- `screenshot` может быть пустым.

`website/data/index.json` — массив кратких записей без полного текста. Его
**не нужно править вручную**: workflow `build-index` пересобирает файл при
любом изменении в `website/data/tickets/` и коммитит результат сам.

## Программа администратора (локально)

Требования: **JDK 17+** и **Maven**. Приложение на JavaFX.

```
admin-app/
├── src/main/java/com/gosupport/
│   ├── Main.java          # окно с двумя вкладками
│   ├── ImportMode.java    # импорт CSV из Google Forms
│   ├── ReplyMode.java     # ответы на обращения
│   ├── GitHubClient.java  # GitHub REST API и атомарные коммиты
│   └── Models.java        # Ticket, AdminReply, Config
├── config.json            # секреты, в .gitignore
└── pom.xml
```

### config.json

```json
{
  "github_token": "github_pat_...",
  "github_owner": "Doinwor",
  "github_repo": "go-support",
  "branch": "main",
  "admin_name": "Главный Админ",
  "admin_avatar_url": "assets/img/logo.png"
}
```

`admin_avatar_url` может быть абсолютной ссылкой (`https://...`) или
относительным путём внутри сайта. Файл `config.json` **никогда** не
коммитится.

### Запуск

```bash
cd admin-app
mvn clean javafx:run
```

### Режим 1 — импорт заявок

1. Скачайте ответы Google Forms в CSV (или выгрузите лист Google Таблиц).
2. Нажмите «Выбрать CSV файл».
3. Программа берёт только строки, где в колонке согласия стоит «Да».
4. Формирует `id`, пропускает уже существующие заявки (защита от дублей).
5. Обновляет `index.json` и отправляет **один атомарный коммит** через
   GitHub Trees API.
6. В логе появится: «Добавлено N, пропущено M».

Ожидаемые заголовки CSV (порядок не важен, допускаются другие формулировки):

| Поле формы | Что ищет программа |
|---|---|
| Отметка времени | `отметка`, `timestamp`, `дата` |
| Как вас подписать? | `подписать`, `автор` |
| К какому проекту относится? | `проект` |
| Краткая тема | `тема`, `заголов` |
| Суть вопроса | `суть`, `вопрос`, `описан` |
| Ссылка на скриншот | `скриншот` |
| Согласие на публикацию | `соглас` |

### Режим 2 — ответы

1. При открытии вкладки программа скачивает актуальный `index.json`.
2. Слева — таблица обращений, строки со статусом `open` подсвечены жёлтым.
3. При выборе заявки справа загружается полный текст.
4. Введите ответ и нажмите «Отправить»: в JSON добавляется `admin_reply`,
   статус становится `answered`, изменения уходят коммитом в GitHub.

После пуша workflow `build-index` обновит ленту, а `deploy-pages` — сайт.

## Настройка Google Forms

Создайте форму со следующими полями:

1. **Как вас подписать?** — короткий текст, обязательное.
2. **К какому проекту относится?** — выпадающий список:
   - GO Ecosystem → WAWE
   - GO Ecosystem → GO Launcher
   - i. студия → Утилиты
   - i. студия → Сайты
   - i. студия → Фильмы
   - i. студия → Игры
3. **Краткая тема** — короткий текст, обязательное.
4. **Суть вопроса** — абзац, обязательное.
5. **Ссылка на скриншот** — короткий текст, необязательное.
6. **Согласие на публикацию** — флажок «Согласен, что обращение будет
   опубликовано», обязательный.

Затем:

1. Вкладка **Ответы** → иконка Google Таблиц: ответы будут собираться в таблицу.
2. Из таблицы: **Файл → Скачать → CSV** — этот файл импортируется в админку.
3. В настройках формы включите сбор адресов почты, если нужен контакт с автором
   (на сайт он не публикуется).

## Токен GitHub

1. GitHub → **Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token**.
2. Repository access: **Only select repositories → Doinwor/go-support**.
3. Repository permissions:
   - **Contents: Read and write** — создание заявок и ответов;
   - **Workflows: Read and write** — если планируете менять workflow из API;
   - **Pages: Read and write** — для настройки публикации.
4. Скопируйте токен в `admin-app/config.json` → `github_token`.

Токен — секрет. Не публикуйте его, не коммитьте `config.json` и обновите
токен, если он попал в чужие руки.

## Публикация

- `build-index` — пересобирает `index.json` и коммитит его.
- `deploy-pages` — публикует папку `website/` на GitHub Pages.

В настройках репозитория: **Settings → Pages → Build and deployment →
Source: GitHub Actions**. Первый деплой запускается автоматически после пуша.

## Добавление обращения вручную

1. Создайте `website/data/tickets/2026-11-01-1200-nick.json` по формату выше.
2. Закоммитьте файл.
3. Actions пересоберут `index.json` и обновят сайт.

## Лицензия и приватность

Обращения публикуются только с согласия авторов. Не добавляйте в заявки
пароли, платёжные данные и другую чувствительную информацию.
